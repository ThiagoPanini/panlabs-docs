# Esteira.gerar

**Function** · `panlabs.esteira.Esteira.gerar`

It validates before writing, and never emits partial output: either the YAML describes the complete pipeline, or there is no YAML. A workflow that runs with a step missing passes, and passing without checking is worse than not running.

With `diff=True` nothing is written. That is the mode the verification pipeline uses to fail when the committed YAML stops being what the Python produces.

## Parameters

<ParamField name="destino" type="Path | str" required>
The directory the YAML is written to. The file name comes from the pipeline name.
</ParamField>

<ParamField name="diff" type="bool" default="False">
Compares against what is on disk and writes nothing. This is the check mode.
</ParamField>

## Returns

The result of the generation. Under `diff=True` it carries the verdict without having touched the disk.

<ResponseField name="caminho" type="Path">
The file written, or the one that would have been written under `diff=True`.
</ResponseField>

<ResponseField name="mudou" type="bool">
True when the generated YAML differs from what was on disk.
</ResponseField>

<ResponseField name="recusas" type="list[dict]">
The refusals found. Empty when the pipeline passes — and when it is not empty, nothing was written.

<Expandable title="list[dict]" defaultOpen>

<ResponseField name="recusa" type="str">
The refusal name, from the closed list.
</ResponseField>

<ResponseField name="ponteiro" type="str">
The offending node, as a dotted path — `trabalhos.verificar.passos[2].uses`.
</ResponseField>

<ResponseField name="detalhe" type="str">
The sentence describing what is wrong at that node.
</ResponseField>

</Expandable>
</ResponseField>

## Errors

| Error | When |
| --- | --- |
| `PassoSemNome` | A step arrived without a `nome`. |
| `ReferenciaNaoFixada` | A third-party action is referenced by tag. |
| `SegredoInline` | A value that looks like a secret would land literal in the YAML. |
| `PermissaoAmpla` | The job permissions resolve to `write-all`. |
