# Esteira

**Type** · `panlabs.esteira.Esteira`

The object standing for a workflow. Constructing it writes nothing to disk: the YAML only exists after `gerar`.

The name is what shows up in the Actions UI, and it also becomes the file name — two workflows with the same name in the same repository overwrite each other silently.

## Parameters

<ParamField name="nome" type="str" required>
The workflow name. It also becomes the file name, lowercased and hyphenated.
</ParamField>

<ParamField name="em" type="list[str]" required>
The events that trigger the pipeline. Takes the Actions event names as they are, untranslated.
</ParamField>

<ParamField name="permissoes" type="dict[str, str] | None" default="None">
The workflow token permissions. Left out, the pipeline inherits the repository default — which tends to be broader than the job needs.

<Expandable title="dict[str, str] | None" defaultOpen>

<ParamField name="contents" type="str">
Repository read access. `read` is enough for any pipeline that does not push a commit.
</ParamField>

<ParamField name="id-token" type="str">
OIDC token issuance. `write` is what lets the job assume an AWS role without a long-lived key.
</ParamField>

</Expandable>
</ParamField>

## Attributes

The constructed object, carrying the jobs added so far.

<ResponseField name="nome" type="str">
The name given at construction time, unnormalized.
</ResponseField>

<ResponseField name="trabalhos" type="list[dict]">
The jobs added by `trabalho`, in the order they came in.

<Expandable title="list[dict]" defaultOpen>

<ResponseField name="nome" type="str">
The job identifier inside the workflow.
</ResponseField>

<ResponseField name="passos" type="list[Passo]">
The job's steps, in execution order.

The fields live on the type's own page: [`Passo`](./passo.mdx)
</ResponseField>

</Expandable>
</ResponseField>
