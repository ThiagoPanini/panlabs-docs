# Create a refund

<VerbBadge verb="POST" /> `/reembolsos`

Refunds a `paga` charge, in full or in part. Repeating creates a second refund — use `Idempotency-Key` to avoid it.

## Parameters

<ParamField name="Idempotency-Key" type="string" required>
A key you choose, up to 255 characters. Repeating the call with the same key and the same body, within 24 hours, returns the original response instead of creating again.
</ParamField>

## Body

<ParamField name="cobranca_id" type="string" required>
The charge to refund.
</ParamField>

<ParamField name="valor" type="integer">
In cents. Omit to refund the full amount.
</ParamField>

<ParamField name="motivo" type="string">
Free-form, yours.
</ParamField>

## Response

<ResponseField name="id" type="string">
The refund identifier, prefixed `reemb_`.
</ResponseField>

<ResponseField name="cobranca_id" type="string">
The refunded charge.
</ResponseField>

<ResponseField name="valor" type="integer">
In cents. Partial is allowed — the sum of refunds never exceeds the original amount.
</ResponseField>

<ResponseField name="motivo" type="string">
Free-form, yours. Shows on the payer statement when the method supports it.
</ResponseField>

<ResponseField name="status" type="string">
Pix and boleto complete in minutes; card can take days, depending on the issuer.

Possible values: `pendente`, `concluido`, `falhou`.
</ResponseField>

<ResponseField name="criado_em" type="string">
When the refund was requested.
</ResponseField>

## Errors

| Status | When |
| --- | --- |
| `400` | The request is not valid against the contract. |
| `401` | The key is missing, invalid, or from another environment. |
| `422` | The amount exceeds the charge’s refundable balance. |
